# 新电脑开发交接文档（东北大学校史地图）

> 给新电脑上的 AI 助手：先把本文读完，再读仓库根目录的 `README.md` 和 `docs/维护与素材接入手册.md`，就能接上开发。
> 如果用户对 Git / GitHub 操作不熟，把 `docs/GitHub使用与同步指南.md` 也一起给他看（里面把克隆、认证、push/pull 同步流程讲得很细）。
> 本文写于 2026-10-11，对应最新提交 `e5d7aa5`（分支 `main`，仓库里只有这一个远程分支）。

## 0. 项目是什么

- 东北大学校史地图网站：Express + EJS + 原生 CSS/JS，**没有数据库**，数据存在 `data/*.json` 里
- 代码仓库：`git@github.com:sixlights741/jindaishi.git`
- 线上站点：`https://neu-xsdt.top`，代码在服务器 `/var/www/xiaoshiditu/jindaishi`，用 pm2 托管、nginx 反向代理
- 线上更新不用手工传代码，服务器从 GitHub 拉（见第 6 节）

## 1. 在新电脑上跑起来

1. 装 Node.js 18+，确认 `node -v` 有输出
2. 拉代码（二选一）：
   - SSH：`git clone git@github.com:sixlights741/jindaishi.git`（需要这台新电脑的 SSH 公钥已加到 GitHub 账号）
   - HTTPS：`git clone https://github.com/sixlights741/jindaishi.git`（国内网络可能不稳）
3. 装依赖：`cd jindaishi && npm install` —— `node_modules/` 被 `.gitignore` 排除，必须自己装
4. 启动：`npm start`（等于 `node src/server.js`，默认端口 3000，可用环境变量 `PORT` 改）
5. 打开 `http://localhost:3000`

**本地登录**：仓库里没有 `data/student_ids.json`，首次启动会用默认学号播种账号，初始密码 = 学号，所以可以用 `20230001` / `20230001` 登录。首次登录会强制改一次密码，改完进主页。

**本地没有管理员账号**（要点）：`data/admin_ids.json` 里写的是 `"1"`，而账号 `1` 只存在于未跟踪的 `data/users.json` 里，所以全新 clone 出来的环境里 `20230001` **看不到「管理员后台」**。想在本地测后台，二选一：

- 最省事：从服务器 `/var/www/xiaoshiditu/jindaishi/data/` 拷 `users.json`（真实账号就都有了，包括 `1`）；
- 或者把 `20230001` 加进本地 `data/admin_ids.json`（**改完别提交**，否则线上会多一个管理员）。

管理员密码规则和普通账号一样：没改过就是学号。

## 2. 仓库里有什么、没什么（重要）

**跟踪的**：`src/`（全部代码）、`public/`（样式、图片、leaflet，含 62 张历史上传图）、`data/places.json`（地点内容）、`data/admin_ids.json`（管理员学号）、`scripts/update-server.sh`（线上更新脚本）、`docs/`、`README.md`、`package.json` / `package-lock.json`

**被 .gitignore 排除的（clone 下来没有）**：

| 文件 | 是什么 | 没有会怎样 |
| --- | --- | --- |
| `data/student_ids.json` | 学号白名单 | 用默认的 3 个学号播种账号 |
| `data/users.json` | 账号 + 密码哈希（bcrypt） | 账号等于重置为默认 |
| `data/ai_config.json` | 后台配的 AI Key | 「讲解小助手」走兜底回答 |
| `data/visit-counter.json` | 累计访问数 | 从 0 开始 |
| `node_modules/` | 依赖 | `npm install` 就有 |
| `.env` | 环境变量 | 本项目不自动读 `.env`，靠终端/面板注入 |

这些数据文件含学号和密钥，**不要提交进仓库**。本地开发不需要它们；想和线上完全一致，从服务器 `/var/www/xiaoshiditu/jindaishi/data/` 拷一份。

## 3. 代码结构

- `src/server.js` —— 唯一的路由文件，所有页面和接口都在这里（约 1000 行）
- `src/services/userStore.js` —— 账号读写：bcrypt 哈希、初始密码=学号、首次登录强制改密、管理员判定
- `src/services/placeStore.js` —— 地点数据读写
- `src/services/uploadedFileName.js` —— 上传图片文件名规范化（修中文乱码用）
- `src/views/*.ejs` —— 页面模板：`login.ejs`（登录方式选择）、`login-account.ejs`（账号密码表单）、`index.ejs`（主页地图）、`place.ejs`（地点详情 + AI 助手）、`admin-*.ejs`、`change-password.ejs`、`not-found.ejs`
- `public/` —— 静态资源；`public/uploads/` 是后台上传的图片（新上传的不会进仓库）
- `data/` —— JSON 数据文件
- `scripts/update-server.sh` —— 服务器更新脚本（内置数据保护）
- `neuweb/323.py` —— 与主流程无关的备用脚本

## 4. 最近一次改动（提交 63ee1fd）做了什么

登录入口从"直接显示账号密码表单"改成"先选登录方式"：

- `GET /login`：登录方式选择页，左右两个圆形按钮 —— 左「登录」跳 `/login/account`，右「访客」POST 到 `/login/guest`
- `GET /login/account`：账号密码表单（密码错了会回填已输入的学号）
- `POST /login/guest`：写入访客会话（`studentId: "访客"`、`isGuest: true`）然后进主页
- `src/server.js` 里的 `requireRealUser` 中间件：访客访问 `/profile/password` 会被跳回主页（`requireAdmin` 本来就会拦访客）
- 主页 `index.ejs` 对访客隐藏「改密码」，退出按钮文案变成「退出访客」
- 样式在 `public/styles.css` 的 `.auth-choice` / `.circle-btn` / `.circle-btn-guest` 几段，含移动端（≤900px）适配

## 5. 开发注意事项（都是踩过的坑）

- **重启服务会清空登录状态**（express-session 存在内存里），本地开发时是正常现象，重新登录即可
- **端口占用**：`src/server.js` 端口被占用时会打印提示并退出，改 `PORT` 或先关掉旧进程（Windows：`netstat -ano | findstr :3000` 找到 PID 后 `taskkill /PID <pid> /F`）
- 数据是**同步读写的 JSON 文件**，没有并发保护，别同时跑两个实例写同一份数据
- **AI 助手**需要环境变量（`OPENAI_API_KEY` / `OPENAI_BASE_URL` / `AI_MODEL`，模板见 `.env.example`）或后台的 AI 配置。注意本项目**不自动读取 `.env` 文件**，要在终端、服务器面板或 PM2 里注入
- **换行符**：shell 脚本必须是 LF（`.gitattributes` 已锁定 `*.sh`），否则 Linux 上会报 `\r: command not found`
- **PowerShell 脚本如果带中文，必须存成 UTF-8 带 BOM**，否则 Windows PowerShell 5.1 会读出乱码
- 中文文件名的图片上传靠 `src/services/uploadedFileName.js` 处理，不要绕过它
- 仓库如果不是私有的，提交前检查一下别把学号、Key、密码带上

## 6. 线上部署与更新（在服务器上操作）

铁律：**线上数据（`data/` 和 `public/uploads/`）永远以服务器为准**，仓库里那份是旧的——`git reset --hard` 会覆盖 `data/places.json`，`rsync --delete` 会删掉后台上传的图片。

更新代码（一条命令，脚本自己会保护数据）：

```bash
cd /var/www/xiaoshiditu/jindaishi && git fetch --depth=1 origin main && git show origin/main:scripts/update-server.sh > /tmp/xsdt-update.sh && sudo bash /tmp/xsdt-update.sh
```

脚本流程：备份数据到 `/root/xsdt-backup-*.tgz` → 停 pm2 → 把 `data/`、`public/uploads/` 改名移出项目目录 → 拉代码 → 放回数据 → 装依赖 → 重启 → 验收。任何一步失败都会把数据放回并恢复服务。

**最容易忘、也最容易踩的一步：拉完代码必须重启进程。** 2026-10-11 就出过这个事故：登录页已经显示新的两个圆钮，但点「登录」和「访客」都 404 —— 因为 pm2 里的进程还是更新前启动的，模板是每次请求从磁盘读的（所以页面变了），而路由是进程启动时注册的（所以新路由不存在）。如果手动 `git pull` 而不是跑上面那个脚本，记得补一句：

```bash
sudo pm2 restart all && sudo pm2 status
```

## 7. 另一台机器上的配套工具：流量监视（不在本仓库）

- 位置：`C:\Users\Administrator\Desktop\traffic-monitor`，是**独立文件夹**（不是 git 仓库），整个复制就能用
- 用途：统计一台 Windows 机器（长期挂机下载/上传）的累计下载、上传流量，可选按周期额度告警
- 用法：双击 `流量监视.cmd` 打开图形面板，按钮有「启动监视 / 停止监视 / 查看报表 / 开机自启 / 设置额度 / 创建桌面快捷方式」
- 技术要点：
  - 只统计**物理网卡**（`Get-NetAdapter -Physical`），自动排除 PXWiFi / OpenVPN / TAP 等虚拟网卡，避免代理隧道把一份流量算两遍
  - 靠网卡的累计字节计数取差值累加，采样间隔不影响精度，重启最多丢一个采样周期
  - 面板定时刷新只用便宜查询（`schtasks` 约 34 ms + 读状态文件），慢查询（WMI 查进程约 300 ms、`Get-ScheduledTask` 1000 ms 以上）只在点按钮时用——早期版本把慢查询放进 3 秒定时器里，窗口卡得没法用
- 完整说明见该文件夹里的 `README.md`
