# 东北大学校史地图：维护与素材接入手册

这份手册用于回答三个实际问题：
1. 如何把单色背景换成“校园实拍虚化背景图”；
2. 其他小组完成手绘图后，你如何快速插入网站；
3. 如何避免常见素材路径和发布错误。
4. 如何使用管理员后台进行增删改。

---

## 一、目录结构速览

核心文件与目录：

- 页面样式：`public/styles.css`
- 地点数据：`data/places.json`
- 详情页模板：`src/views/place.ejs`
- 图片目录：`public/images/`
- 手绘图目录：`public/images/drawings/`

## 二、替换全站背景图（校园照片虚化版）

### 1) 准备素材

建议参数：
- 分辨率：不低于 `1920x1080`
- 单图大小：建议 `300KB ~ 1.5MB`
- 构图：校园全景/主楼/校门，避免过于杂乱

### 2) 放置文件

把你的背景图命名为：

`campus-bg.jpg`

放到：

`public/images/campus-bg.jpg`

### 3) 样式机制说明

系统已在 `public/styles.css` 中启用：
- 背景图层（自动铺满）
- 虚化与饱和度增强
- 暗色遮罩和光晕叠层

因此你只需“替换同名文件”，一般无需改代码。

### 4) 自定义虚化强度（可选）

在 `public/styles.css` 查找 `body::before`：
- `filter: blur(8px) saturate(1.2);`

可按需调节：
- 更虚化：`blur(10px)` 或 `blur(12px)`
- 更清晰：`blur(5px)`

## 三、插入其他组手绘图（推荐流程）

## 1) 收集并重命名

建议统一命名格式：

`地点id-序号.jpg`

例如：
- `lib-old-a.jpg`
- `lib-old-b.jpg`
- `main-building-01.png`

## 2) 放入手绘图目录

复制到：

`public/images/drawings/`

## 3) 修改地点数据

打开 `data/places.json`，找到目标地点，在该对象里编辑 `drawings` 字段。

示例：

```json
{
  "id": "lib-old",
  "name": "原图书馆旧址",
  "lat": 41.7662,
  "lng": 123.4289,
  "period": "1950s-1980s",
  "summary": "见证学校早期教学与科研资料积累的重要地点。",
  "content": "......",
  "image": "/images/drawings/lib-old-cover.jpg",
  "drawings": [
    {
      "url": "/images/drawings/lib-old-a.jpg",
      "caption": "原图书馆旧址手绘立面图"
    },
    {
      "url": "/images/drawings/lib-old-b.jpg",
      "caption": "原图书馆旧址平面草图"
    }
  ]
}
```

字段说明：
- `image`：详情页顶部主图
- `drawings`：下方画廊图（可多张）
- `drawings[].url`：图片访问路径（以 `/images/...` 开头）
- `drawings[].caption`：图片说明文字

## 4) 刷新页面验证

进入地图 -> 点击该地点 -> 检查：
- 主图是否显示
- 画廊是否出现
- 每张图说明是否正确

## 四、常见错误与排查

### 1) 图片不显示

排查顺序：
1. 文件是否确实在 `public/images/drawings/`
2. JSON 路径是否写成 `/images/drawings/xxx.jpg`
3. 扩展名是否一致（`.jpg` 和 `.png` 不可混）
4. 文件名是否大小写一致

### 2) 页面报错打不开

高频原因是 `data/places.json` 格式错误（如多逗号、少引号）。

建议：
- 修改 JSON 时使用 VS Code 自动格式化
- 每次只改一个地点，边改边刷新

### 3) 画廊不出现

`drawings` 为空数组时不会显示画廊，这是预期行为。

### 4) 上传图片后说明显示乱码

早期版本读取上传文件名时用错了字符集，中文文件名（如 `老校门.jpg`）会显示成 `èæ ¡é¨` 这类乱码。

现已修复：

- 新上传的图片若没填“手绘图说明”，会用还原后的文件名作说明；
- 文件名无法可靠还原时，说明显示为“上传图 1 / 上传图 2”；
- 之前已经存成乱码的说明会在读取时自动还原，前台不再显示乱码；重新保存该地点后写回 `data/places.json`。

排查建议：若仍看到乱码，先确认服务器已更新到最新代码并重启（`npm start`）。

### 5) 填了“手绘图说明”，保存后一刷新就没了

早期版本只在“同一次提交里同时还上传了新图片”时才保存说明框的内容：单独修改已有图片的说明再保存，会被整段忽略。

现已修复：说明框按行对应画廊里的图片顺序，编辑页会自动回填已有说明，单独改说明保存同样生效。

若仍出现说明丢失，先确认服务器已更新到最新代码并重启。

## 五、建议的协作规则（小组）

为避免混乱，建议你在组内约定：

1. 每个建筑给一个固定 `id`（不要改来改去）；
2. 所有图片先放共享网盘，最终统一由你拷到 `public/images/drawings/`；
3. 文案先在共享表格定稿，再录入 `data/places.json`；
4. 每次上线前备份 `data/places.json`。

## 七、管理员后台使用说明（新增）

## 1) 设置管理员账号

编辑文件：`data/admin_ids.json`

示例：

```json
[
  "20230001",
  "20230009"
]
```

说明：
- 这些学号登录后将显示“管理员后台”入口；
- 若某账号已在 `users.json` 中存在，重新登录即可读取管理员权限。

## 2) 后台入口与功能

- 入口路径：`/admin`
- 主要功能：
  - 新增地点
  - 编辑地点（含主图、经纬度、文案）
  - 删除地点
  - 上传手绘图并填写说明
  - 填写 B 站视频链接（最多 5 条）

## 3) 手绘图上传与说明填写

在后台“手绘图上传”里选择图片（可多选），保存后图片存入 `public/uploads/`，并按顺序出现在详情页的画廊里。

“手绘图说明”文本框按行填写，**第 1 行对应第 1 张图**，第 2 行对应第 2 张，以此类推：

- 编辑已有地点时，这个框会预先填好现有说明，直接改某一行的文字再保存即可；
- 某一行留空，表示这张图不写说明；
- 行数少于图片数时，多出来的图片保留原有说明；新上传的图片若没有对应说明行，则用文件名作说明。

预览区每张图下方会标出“第 N 张：说明”，填写时可对照；删除某张图时，说明框里对应的那一行会一起删掉，不会串行。

## 4) 地点视频（最多 5 条）

“B站视频链接”文本框按行填写，**一行一条，最多 5 条**：

- 整条链接（`https://www.bilibili.com/video/BV1xxxxxxx`）、BV 号、av 号都能识别；
- 框下方提示“已填 N / 5 条”，超过 5 条保存时会提示删减，不会静默丢弃；
- 预览区会按保存后的样子显示每个视频，最多 5 个。

前台详情页把这几个视频排成网格（窄屏单列、宽屏两列），只有滚动到可见位置时才加载，避免一次加载多个播放器卡顿。

说明：早期数据里存的是单个 `videoUrl` 字段，现在统一为 `videoUrls` 数组，读取时自动兼容，管理员下次保存该地点后自动写回新格式。

## 5) 推荐操作流程

1. 同组同学交付手绘图与视频；
2. 进入管理员后台编辑地点，上传手绘图并逐行填写说明，粘贴视频链接（最多 5 条）；
3. 点击保存后立即在前台预览验证。

---

## 6) 直接写入 JSON（高级，可选）

也可以不走后台上传，直接编辑 `data/places.json`：

```json
"videoUrls": [
  "https://www.bilibili.com/video/BV1xxxxxxxx",
  "BV1yyyyyyyy"
],
"drawings": [
  { "url": "/images/drawings/main-building-01.jpg", "caption": "主楼南立面手绘图" },

```

说明里可以包含竖线 `|`，不会被截断。

## 八、服务器更新代码与重启（实战版）

### 0) 先记住一条原则

**线上数据以服务器为准，仓库只负责代码。**

后台上传的图片、地点视频、手绘图说明，全部存在服务器上，仓库里那份是旧的：

| 内容 | 位置 | git 管吗 |
| --- | --- | --- |
| 地点、图片路径、视频链接、手绘图说明 | `data/places.json` | 跟踪，但线上会更新，别退回旧版 |
| 上传的图片文件 | `public/uploads/` | 新上传的文件不在仓库里 |
| 账号密码 | `data/users.json` | 不跟踪（已忽略） |
| AI 配置（含 Key） | `data/ai_config.json` | 不跟踪（已忽略） |

所以更新代码时必须**保护 `data/` 和 `public/uploads/`**：`git reset --hard` 会用仓库旧版本覆盖 `data/places.json`，`rsync --delete` 还会删掉服务器上新上传的图片。

本节只保留**唯一推荐方案**：一键脚本（已内置数据保护）。复制整段到服务器执行即可。

前提：本地改动已经 `git commit` + `git push` 到 GitHub 的 `main`（服务器是从 GitHub 拉代码的）。

适用场景：
- 服务器代码落后、线上数据较新时同步代码；
- `git pull/fetch` 偶发失败；
- `HTTP2 framing layer` 报错；
- 目录权限/`safe.directory` 问题；
- 需要自动兜底到压缩包更新。

### 1) 一键更新（已保护线上数据，先 Git，失败自动走压缩包兜底）

```bash
set -e

APP_DIR="/var/www/xiaoshiditu/jindaishi"
REPO_HTTP="https://github.com/sixlights741/jindaishi.git"
CODELOAD_URL="https://codeload.github.com/sixlights741/jindaishi/tar.gz/refs/heads/main"
TMP_TGZ="/tmp/jindaishi-main.tar.gz"
TMP_DIR="/tmp/jindaishi-main"

echo "[1/9] 基础修复..."
git config --global --add safe.directory "$APP_DIR" || true
git config --global http.version HTTP/1.1
git config --global http.lowSpeedLimit 0
git config --global http.lowSpeedTime 999999
sudo chown -R admin:admin "$APP_DIR"

echo "[2/9] 进入项目目录..."
cd "$APP_DIR"

if [ -e data.online ] || [ -e public/uploads.online ]; then
  echo "[STOP] 发现上次更新遗留的 data.online / public/uploads.online。"
  echo "       那是线上数据，请先确认内容后再手动删除，然后重新执行本脚本。"
  exit 1
fi

echo "[3/9] 备份线上数据到 /root（可回滚）..."
sudo tar czf "/root/xsdt-backup-$(date +%F-%H%M).tgz" data public/uploads
sudo ls -lh /root/xsdt-backup-*.tgz | tail -1

echo "[4/9] 停服务，并把线上数据就地挪开（改名，不占额外空间）..."
sudo pm2 stop all || true
mv data data.online
mv public/uploads public/uploads.online

echo "[5/9] 确认远程..."
git remote set-url origin "$REPO_HTTP" || true

echo "[6/9] 拉取代码（只取代码，数据已挪出项目目录）..."
if git fetch --depth=1 origin main && git reset --hard origin/main; then
  echo "[OK] Git 拉取成功"
else
  echo "[WARN] Git 拉取失败，进入压缩包兜底流程..."
  rm -rf "$TMP_DIR" "$TMP_TGZ"
  curl -L --retry 5 --retry-delay 2 -o "$TMP_TGZ" "$CODELOAD_URL"
  tar -xzf "$TMP_TGZ" -C /tmp
  rsync -av --delete \
    --exclude ".git" \
    --exclude "node_modules" \
    --exclude "data/" \
    --exclude "public/uploads/" \
    "$TMP_DIR"/ "$APP_DIR"/
  echo "[OK] 压缩包覆盖完成"
fi

echo "[7/9] 放回线上数据（仓库里的旧数据以对比方式处理）..."
mv data data.fromrepo
rm -rf public/uploads
mv data.online data
mv public/uploads.online public/uploads

if [ -f data.fromrepo/places.json ]; then
  # 提醒：如果组员在手改 places.json 后推过代码，那些地点线上可能没有
  node -e '
    const fs = require("fs");
    const repo = JSON.parse(fs.readFileSync("data.fromrepo/places.json", "utf8"));
    const live = JSON.parse(fs.readFileSync("data/places.json", "utf8"));
    const liveIds = new Set(live.map((p) => p.id));
    const onlyRepo = repo.filter((p) => !liveIds.has(p.id)).map((p) => `${p.id}(${p.name})`);
    console.log(onlyRepo.length ? `[注意] 仓库版里有线上没有的地点：${onlyRepo.join("、")}` : "[OK] 仓库版没有线上缺失的地点");
  ' || echo "[WARN] 对比失败，请手动核对 data.fromrepo/places.json"
  rm -rf data.fromrepo
fi

echo "[8/9] 安装依赖并重启..."
npm install --omit=dev
sudo pm2 restart all || sudo pm2 start src/server.js --name neu-xsdt
sudo pm2 save

echo "[9/9] 验收..."
test -f src/services/uploadedFileName.js \
  && echo "[OK] 新模块 src/services/uploadedFileName.js 已就位" \
  || echo "[ERROR] 缺少 src/services/uploadedFileName.js，代码没更新完整，服务会起不来"
sudo pm2 status
curl -I https://neu-xsdt.top || true

echo "完成。确认页面正常后，可删除 /root/xsdt-backup-*.tgz 里较旧的备份。"
```

### 2) 更新后怎么确认数据和代码都对

1. `sudo pm2 status` 显示 `online`，`curl -I https://neu-xsdt.top` 返回 `200`；
2. 打开一个**最近在后台加过内容**的地点详情页，图片、视频、手绘图说明都在；
3. 打开后台编辑该地点：
   - “手绘图说明”框里应当自动带出已有说明；
   - “B站视频链接”框里应当带出已有链接，可填多行、最多 5 条；
4. 随便上传一张**中文文件名**的图片（不填说明），保存后前台说明应显示中文，不出现 `æµ‹è¯•` 这类乱码。

### 3) 固定运维习惯（避免再次踩坑）

- 重启统一使用：`sudo pm2 restart all`
- 更新后验收：`sudo pm2 status` + `curl -I https://neu-xsdt.top`
- 更新代码前先按上面第 3 步备份；**永远不要把 `data/` 和 `public/uploads/` 回滚到仓库版本**，那是线上后台上传的全部内容
- 如果误操作覆盖了数据：`sudo tar xzf /root/xsdt-backup-<时间>.tgz -C /var/www/xiaoshiditu/jindaishi/` 即可还原
- 想让仓库也有一份线上数据做备份，可以在本地把服务器上的 `data/places.json` 拉回来提交（可选，注意 `public/uploads/` 体积较大）
